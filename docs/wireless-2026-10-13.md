# 无线投屏与控制 · 2026-10-13

无线连接运行在 APK 内，安卓与 iPhone 通过局域网直接传输。AirPlay 接收器提供视频，无线 RemotePairing TCP 隧道提供触控，两条链路分别显示状态。

## 使用

1. 首次无线控制：开启 iPhone 开发者模式，通过 USB 连接安卓一次，完成开发者镜像与无线配对。确认 iPhone 上的信任提示。配对记录保存在安卓应用私有目录。
2. 两台设备连接同一 Wi-Fi。点「连接 iPhone → 无线投屏与控制 → 启动无线连接」。
3. 在 iPhone「控制中心 → 屏幕镜像」选择 `iMirror Lite · 安卓型号`。首个实际解码帧显示后，界面才报告已连接。
   若 iPhone 请求 AirPlay 配对码，在安卓显示四位 PIN 后输入 iPhone。配对事务按发送端 IP 保留三分钟，可跨 TCP 连接完成。
4. 应用发现同一投屏发送端的 RemotePairing 服务后自动建立无线控制；继续使用已有的最多五指触控、三键导航与快捷操作。
5. iPhone 重启后，开发者镜像可能需要通过 USB 再次准备。无线视频本身不要求开发者模式；控制要求 iOS 18+。
6. 点断开或离开应用会释放触点、关闭隧道与接收端口、撤销 Bonjour 广播并释放组播锁。

当前提供 H.264 屏幕镜像，不传输音频。网络需要允许两台设备互访和 mDNS 组播，访客 Wi-Fi 的客户端隔离会影响发现与连接。

## 实现与验证范围

- 使用 Android NSD 发布 `_airplay._tcp` / `_raop._tcp`，发现 `_remotepairing._tcp` / `_remotepairing-manual-pairing._tcp`。Wi-Fi 组播锁仅在无线会话期间持有。
- AirPlay 的 Ed25519 身份保存在应用私有目录。执行 X25519 / Ed25519 Pair-Verify、FairPlay 流密钥解包、连续 AES-CTR 视频解密，再送入已有 MediaCodec / SurfaceView。
- PlayFair JNI 检查固定长度与模式值。请求、视频报文、连接数量和发现队列均有上限。
- 无线控制使用独立 RemotePairing 记录、TLS 1.2 PSK 和纯用户态 IPv6/TCP 栈，不需要 Root、内核 TUN 或电脑中转。关联当前投屏发送端与同一个 DNS-SD 主机的 IPv4 / IPv6 地址后连接控制服务。
- USB 首次连接通过受信任的 RSD 服务准备无线配对，已有配对时跳过准备步骤。
- Python 回归覆盖签名配对、分片视频、AES-CTR 跨帧状态、格式与长度验证、连续启动关闭，以及控制候选与服务丢失处理。
- 打包运行时检查使用合成发送端验证真实 Android 端套接字、原生 PlayFair、签名配对、加密视频接收与 TLS-PSK 用户态隧道；既有测试另行验证真实 H.264 硬件解码、PixelCopy 与五指 MotionEvent 路由。

合成发送端和运行时检查不能证明真实 iPhone 的 AirPlay / HID 兼容性。10 月 14 日上午已完成真实无线首帧与用户重连确认，并保存无线控制配对；修复后的真实无线控制仍待复测。见 [实测和地址发现修复](wireless-live-2026-10-14.md)。

## 10 月 14 日本地修复与真机检查

- EBG-AN00 / Android 12 / ARM64 已安装当前开发 APK。真实局域网可发现 AirPlay 广播，并通过 Wi-Fi 读取接收器 `/info`；修复 Android 12 的 NSD 注册回调服务类型可能为空导致的崩溃。
- 真实 iPhone（192.168.137.199）已连接安卓接收器。首次失败为 `/pair-pin-start` 未实现，随后已增加 SRP6a（SHA1 / 2048 位、Apple 40 字节会话密钥）与 AES-GCM 配对。
- 第二次失败为 iPhone 显示 PIN 后关闭旧 TCP，输入 PIN 后从新 TCP 调用 `/pair-setup-pin`，旧代码丢失事务而返回 403。现将事务保留在接收器内，按发送端 IP 隔离并设置三分钟有效期；错误认证返回 470。
- 本地 71 项回归通过，包含 PIN 各阶段使用不同 TCP 的完整流程、错误 PIN 拒绝、发送端隔离和过期清理。IPv4 与 IPv6 均覆盖，接收器使用同一端口的双栈监听，兼容 NSD 发布的 A / AAAA 记录。
- 最后一次安卓打包运行时检查返回 `RUNTIME_SMOKE_OK`，覆盖跨连接 PIN、原生 PlayFair、加密 AirPlay 视频、TLS-PSK 用户态隧道、NSD 注册、H.264 → MediaCodec → SurfaceView / PixelCopy 与五指 MotionEvent。
- 真实 iPhone 在第二次失败后停止测试，修复后的真实无线首帧与无线控制尚未验收。最终构建与测试日志在 `artifacts/wireless-build-final.log`、`artifacts/wireless-tests.log`、`artifacts/wireless-runtime-arm64-final.log`，真实失败握手摘录在 `artifacts/wireless-iphone-attempts.log`。
