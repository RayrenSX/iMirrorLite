# 全链路审查记录 · 2026-10-11

范围：Android USB 枚举与授权、QuickTime、usbmux、Lockdown 配对、DDI、用户态隧道、HID、MediaCodec/TextureView、取消与资源释放。用户给安卓充电期间，仅在本地与模拟器执行复测。

## 已修复

| 问题 | 后果与修复 |
| --- | --- |
| Android 返回的 USB 序列号带尾部 NUL | 序列化到 usbmux plist 时失败；去除 NUL 并规范化序列号，已在真机恢复配对与单指通道 |
| QuickTime 重新枚举触发新 Activity | 原连接被新页面打断；改为 singleTask，并通过 onNewIntent 继续当前连接 |
| 取消后迟到的 USB 授权回调 | 已取消的连接仍可能启动；增加连接状态与请求编号校验 |
| 收到 TCP FIN 时丢弃同包载荷 | Lockdown/TLS 最后一段响应丢失；先保存尾部载荷，再确认 FIN，relay 读尽后退出 |
| 已关闭 mux 连接未从索引释放 | 反复连接后积累连接对象与端口；FIN/RST/close 均回收 |
| USB 接收窗口不随缓冲变化 | 消费慢时持续累积内存；限制缓冲并在应用消费后更新窗口 |
| 乱序段与后续连续段重叠 | 数据无法连续交付或重复；按已确认序号剔除重叠与重复数据 |
| TCP 数据偏移、mux magic、HID 字段数量缺少检查 | 畸形响应可能错位解析或长时间循环；增加边界检查与回归用例 |
| HID 属性嵌套、Contact ID/Count 范围未充分检查 | 可能忽略有效描述符，或宣称无法编码的多指能力；解析 Swift Codable data 并收紧能力判定 |
| 9021 媒体认证错误阻断已存在的 HID | 实际两台 iPhone 均出现；仅对明确的 9021 或未发布 DisplayService 转入真实 HID 通道探测 |
| 取消异步任务未通知镜像下载线程 | 退出后仍继续下载、延迟释放进程；清理开始时通知停止，流式校验镜像减少内存峰值 |
| 已收到编码帧即显示“投屏已连接” | 解码失败也会显示成功；改为 TextureView 实际收到帧后确认显示 |
| 解码输出线程异常被静默忽略 | 页面可能停帧但不报错；将解码故障传回会话 |
| 闲置页面持续保持亮屏 | 充电慢、额外耗电；仅运行会话期间保持屏幕唤醒 |
| 入站 usbmux v2 标记只接受 `0xfeedface` | 真机 iOS 26.6.2 / 18.7.8 返回 `0xfaceface`，严格校验误拒绝控制响应；接受已观察到的设备标记，出站仍为 `0xfeedface`，其余非法标记继续拒绝 |
| 重复 VERSION 响应按 v2 头解析 | 重连时将版本字段误认作 magic；VERSION 始终按 v1 协商帧解析 |
| 按 Android 版本启用解码器低延迟选项 | 海思 OMX 解码器因不支持该选项而配置失败；改为查询具体解码器的能力后启用 |
| TextureView 的非视频刷新被当成首帧 | 无编码帧的会话退出时也可能触发刷新；要求已收到编码帧且会话没有错误，再确认首帧 |
| Java 异常仅显示 `IOException` | 通过 `getMessage()` 保留 USB 错误详情；已确认初始视频写入返回 `-110`（超时） |
| 发现 Valeria 描述符就跳过投屏启动请求 | 描述符不能证明 iOS 已启动投屏；新连接明确发送一次 vendor 启动请求，并记录结果 |
| 同步视频 USB ioctl 无法保留超时前收到的前缀 | 改用异步 URB，取消后先回收请求再释放 JNI 缓冲；保存 IN 已接收数据，OUT 不重放。IN/OUT 共用回收队列时按请求归属分发完成 |
| 视频停止后未等待设备释放 | 保持读取线程运行，停止请求新帧，回复 SYNC STOP，并在收到两条 RELS 后发送最终 HPD0；等待上限为握手前 1 秒、握手后 6 秒。回归覆盖并发停止、分片 RELS、迟到媒体和失败写入不重放；12 mini 多次真机退出已收到两条 RELS，随后重新连接成功 |
| USB 完成被另一收发线程取走后缺少唤醒 | 每个请求增加 eventfd，完成分发时唤醒拥有者，避免它继续等待完整的 USB 超时 |
| 请求下一帧依赖 Java 转换与解码完成 | 完整收到 FEED 后先发 NEED，再处理当前帧；采用与桌面版一致的 Valeria 投屏协商 |
| 频繁创建数组与重复转换解码配置 | 视频原生读取扩大到 64 KiB，复用读取缓冲，并缓存 Java 数组类型、视频回调与 CSD |
| 解码输入不足时丢失参考帧 | 排出已有输出并有界等待输入，避免丢一个参考帧后等待后续 IDR；提供 60 fps 解码性能提示 |
| 解码帧立即成批提交导致显示丢帧 | 使用 SurfaceView 直接合成，解码线程按 16.67 ms 间隔安排显示，初始 12 ms、未来上限 25 ms。Choreographer 主线程版实测较差已撤回。参考帧完整解码，稳定期系统实测 59.10 fps、重连 58.74 fps |
| 原镜像下载源在安卓被重置连接 | 使用同一 Git blob 的 API 备用源，重新下载并保持长度和摘要校验；本机已完成三个镜像文件下载并建立验证缓存 |
| Apple TSS 的私有根证书不在 certifi 中 | 仅为 TSS 请求使用 Apple 官方公开根证书，保留证书链和主机名验证；安卓已完成真实 TSS 签名、镜像 USB 上传和挂载，并建立 HID 通道 |

新增应用私有连接日志和原生 USB bulk 错误诊断。原生层使用 UsbManager 已授权的文件描述符，不需要 Root；保留 errno，区分超时与端点错误。

## 仍未解决

1. **持续操作帧率、其他设备与长时间稳定性仍待验收。** 当前短排程版 12 mini 稳定期 45 秒实测 59.10 fps、重连后 30 秒为 58.74 fps，收到完整包至显示平均约 54–55 ms，用户确认「延迟明显降低」。仍有少量 33 ms 间隔，操作期间诊断有约 49–56 fps 的窗口，不能宣称始终满 60 fps。iPhone18,3 / iOS 26.6.2 尚未用当前版复测。旋转、长时间运行、拔线异常恢复仍需完整验收。
2. **多指未实测通过。** 实际 HID 通道没有返回可用的并行触点描述符，当前真实设备降为单指；合成五指编码测试不证明 iPhone 接受五指手势。
3. **无线功能已接入，真实 iPhone 验收未完成。** 2026-10-13 至 14 日已加入 AirPlay 接收器、NSD 广播与发现、PIN 配对、USB 首次无线配对、TLS-PSK 用户态隧道及界面。安卓运行时和本地回归通过；真实 iPhone 两次失败已定位并本地修复，等待真实首帧与无线控制复测。见 `docs/wireless-2026-10-13.md`。
首次 DDI 流程已补齐真机验证：12 mini 重启后由安卓下载并校验镜像，根证书修复后成功完成真实 Apple TSS 签名、15 MiB 镜像 USB 上传与挂载，随后打开 HID 通道。证据：`artifacts/android-tss-vsync-session.log`。
