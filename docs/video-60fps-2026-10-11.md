# USB 视频 60 fps 真机记录

设备：EBG-AN00 / Android 12 / ARM64，USB 直连 iPhone 12 mini / iOS 18.7.8。电脑仅通过无线 ADB 安装和读取诊断，未中转视频。

## 测量结果

| 阶段 | 测量 |
| --- | --- |
| 首次恢复画面 | 约 10–20 fps，用户反馈明显卡顿 |
| 收帧优化后、未安排呈现时间 | 接收约 60 fps；SurfaceFlinger 实际呈现 51.98 fps，126 个样本内有 17 次超过 25 ms 的间隔 |
| 早期调度版的一段稳定期 | 32 个约一秒窗口平均接收 59.99 fps、渲染回调 59.19 fps，单窗口 55.4–61.3 fps |
| 同一段系统合成器 | 126 个实际呈现时间戳，59.90 fps，中位间隔 16.56 ms；一次间隔超过 25 ms，最大 33.51 ms |
| 后续重连 | 126 个实际呈现样本为 49.32 fps，其中 28 个间隔超过 25 ms；用户反馈触控时与平时均有明显延迟 |
| 加入延迟诊断后 | 收到完整视频包至显示回调累计平均约 148 ms，启动峰值 421 ms；滑动时解析队列约 70 ms |
| 视频移至 Java 后 | 上述显示年龄约 110 ms，安卓输入入队至 HID 写入返回约 3 ms；用户确认有改善，但仍明显延迟 |
| 海思厂商低延迟参数后 | 解码器保留约 1–2 帧，上述显示年龄约 55–70 ms；短缓冲调度版系统实际呈现 55.47 fps，尚不能宣称稳定 60 fps |
| 本次 Choreographer 主线程呈现 | 连续 30 秒系统实际呈现 52.95 fps；显示年龄约 67 ms |
| 本次解码完成后立即呈现 | 连续 30 秒系统实际呈现 56.40 fps；显示年龄约 50 ms |
| 当前短排程版 | 首段 30 秒 58.41 fps；稳定期 45 秒 59.10 fps；正常断开重连后 30 秒 58.74 fps。显示年龄约 54–55 ms；用户确认「延迟明显降低」 |
| 当前短排程版后续操作期 | 连续 30 秒 55.03 fps，最大间隔 66.64 ms；操作负载下尚未稳定满 60 fps |
| 独立 Choreographer 线程、两帧输出缓冲实验 | 连续 30 秒 56.33 fps，显示年龄约 81 ms；收益差且延迟较大，已撤回 |

分辨率为 1082×2340。窗口内计数可能因起止边界及异步回调略超过 60；系统实际呈现时间戳用于独立核对。启动配对、解码器预热和旋转时不保证立即达到稳定帧率，此记录也不代表所有设备或长时间运行都已验收。

## 当前改动

- USB 视频 IN/OUT 共用完成队列时，以 eventfd 唤醒请求拥有者。
- 完整收到 FEED 后立即请求下一帧，Java 转换和解码与下一帧编码重叠。
- 使用桌面 iPhoneMirror 相同的 Valeria 协商，视频读取为 64 KiB，复用读取缓冲。
- 视频读取、组包、NEED、NAL 转换与 MediaCodec 输入留在 Java 视频线程；仅少量协商消息与格式描述进入 Python。避免逐帧 Java/Python 字节数组往返及其队列积压。
- 海思解码器仅在支持时启用低延迟，并提供 60 fps 的帧率、工作速率与优先级提示。
- 输入缓冲暂不可用时排出输出并有界等待，保留参考帧；稳定测试中未跳过参考帧。
- 海思 OMX 额外使用 `vendor.hisi-ext-low-latency-video-dec.video-scene-for-low-latency-req=1` 与 `video-scene-for-low-latency-rdy=-1`；配置失败时重新创建解码器并退回基础格式。参数依据 [Moonlight 的 Kirin 兼容路径](https://github.com/moonlight-stream/moonlight-android/blob/master/app/src/main/java/com/limelight/binding/video/MediaCodecHelper.java)，在本机测到缓冲从约 4 帧降至 1–2 帧。
- SurfaceView 直接合成；显示提交在解码输出线程完成，不等待主线程 Choreographer。每帧目标间隔 16.67 ms，初始排程 12 ms、未来上限 25 ms，停顿后重新建立时序。参考帧均完整解码，仅在多个输出同时可用时丢弃旧的已解码画面。解码排出周期为 2 ms；每次重建解码器重置排程与诊断计数。
- 退出时继续回复 SYNC STOP，接收两条 RELS 并发最终 HPD0；多个真机会话退出与重连已成功。

## 验证与证据

当前 APK、测试 APK、lint 构建通过（0 errors / 17 warnings），34 项 Python 回归通过。当前短排程版在 ARM64 真机得到 `RUNTIME_SMOKE_OK`：覆盖碎片化控制包与视频包、NEED 先于解码、停止后的帧抑制、格式/数据/时间戳保持、Apple 根证书加载、同一 VideoDecoder 关闭并重建 MediaCodec 后再次显示，以及 PixelCopy 的 SurfaceView 红色像素。此前 Choreographer 版也通过模拟器与 ARM64 运行时检查，但真实帧率较差，已替换为当前短排程版。

延迟统计以安卓收到完整采样包的 monotonic 时间为 PTS，显示回调使用同一时钟。它不含 iPhone 的触控处理、视频编码及收到完整包之前的 USB 时间，不能当作触控到画面的端到端延迟。触控统计也只到 HID 写入返回，不证明 iPhone 已处理事件。

## 充电后复测

安卓恢复调试后，先安装 TSS 根证书修复和 Choreographer 版，完成 ARM64 运行时验证。12 mini 已在安卓端完成真实 Apple TSS 签名、15 MiB 镜像 USB 上传与挂载，随后建立直接单指 HID 通道。证据：`artifacts/android-tss-vsync-session.log`。

本次比较主线程 Choreographer、立即呈现、禁止 Surface 默认丢帧、短排程、独立 Choreographer 线程两帧缓冲五种路径。禁止丢帧实测为 56.52 fps，未明显优于立即呈现，已撤回；独立刷新线程为 56.33 fps、约 81 ms 显示年龄，也已撤回。当前保留用户确认延迟明显降低的短排程版。稳定期 45 秒的 2666 个实际呈现帧中有 52 次间隔超过 25 ms，最大 33.55 ms，不能宣称始终满 60 fps。后续操作期间的连续 30 秒为 55.03 fps，诊断仍出现约 49–56 fps 的窗口，持续操作时的帧率稳定性仍可进一步优化。
